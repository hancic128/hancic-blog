# Hancic 分享卡片显示功能设计文档

- 日期：2026-08-16
- 状态：已确认（经 brainstorming 逐步收敛）
- 项目：`hancic-blog`
- 范围：为文章与独立页面增加**外部平台分享卡片预览**能力，不做站内外链预览卡片，不做动态分享图生成。

## 1. 背景与目标

当前 `hancic-blog` 已具备文章、独立页面、前台主题与站点设置能力，但文章链接分享到飞书、Telegram、X、Slack 等平台时，卡片预览信息不完整。目标是在**不引入额外内容系统、不新增复杂图片生成链路**的前提下，让公开页面输出标准社交分享元数据，并做到：

- 文章与独立页面被分享时，外部平台可抓到稳定的标题、摘要、URL、站点名与图片
- 分享卡片的数据来源简单、确定、可预测
- 第一版不引入每篇文章独立分享图，也不做动态封面生成
- 前台改动尽量集中在现有 SSR 渲染与主题模板层，保持双主题实现一致
- 后续若要升级动态 OG 图，可以在不推翻本方案的前提下演进

## 2. 已确认范围

### 2.1 要做

- 文章详情页分享卡片元数据输出
- 独立页面分享卡片元数据输出
- `canonical` 链接输出
- Open Graph 基础字段输出
- Twitter Card 基础字段输出
- 分享摘要自动回退规则
- 默认分享图直接复用站点 Logo
- 统一使用绝对 URL 输出 `canonical`、`og:url`、`og:image`
- 为运行时增加明确的站点绝对地址配置项（如 `site_url`）

### 2.2 不做

- 站内外链预览卡片
- 每篇文章单独上传分享图
- 动态生成文章专属分享图
- 平台 SDK 接入
- 登录后分享、社交回流、分享统计
- 针对单个平台做特化页面适配

## 3. 方案对比与结论

### 方案 A：只补文字类 meta，不提供图片

实现最简单，能解决大部分“分享出去无标题/无摘要”的问题，但很多平台展示会偏素，成品感较弱。

### 方案 B：标准 meta + 默认分享图（推荐）

在标准字段基础上，统一提供可抓取图片，且默认图直接复用站点 Logo，不引入新图片管理流程。

### 方案 C：标准 meta + 动态文章分享图

传播效果最好，但会引入新的图片生成与缓存链路，超出本期最小闭环。

**结论：采用方案 B。**

## 4. 功能边界

本次功能只解决“文章或页面链接在外部平台被抓取时如何展示卡片”的问题，不扩展到站内卡片体系。

### 4.1 文章页

文章详情页需要输出完整的分享 meta，保证文章链接被外部平台抓取时，能展示：

- 标题
- 摘要
- 站点名
- 标准 URL
- 默认分享图（站点 Logo）

### 4.2 独立页面

独立页面（如 `/page/{slug}` 与 `/about`）也应支持同样的分享卡片能力，避免站内公开内容在分享时表现不一致。

### 4.3 分享按钮

前台是否增加“复制链接 / 分享”按钮不是本期核心目标；即便不增加前台按钮，只要页面头部 meta 正确，外部平台分享卡片功能就已成立。

## 5. 架构设计

### 5.1 总体思路

沿用现有 `src/web/front.rs` + 主题模板的 SSR 渲染模式：

- 后端负责组装分享卡片上下文数据
- 主题模板负责把数据输出到 `<head>` 中的标准 meta 标签
- 不在前端运行时通过 JS 计算分享字段

这样可以保证：

- 抓取机器人无需执行 JS 也能拿到完整信息
- 逻辑集中在后端渲染层，便于双主题统一维护
- 后续若增加更多 meta 字段，只需扩展上下文与模板

### 5.2 改动边界

预计改动点集中在：

- `src/web/front.rs`
  - `post_page`
  - `page_page`
  - `about_page`
  - 公共上下文拼装辅助函数
- `themes/default/templates/post.html`
- `themes/modern/templates/post.html`
- `themes/default/templates/page.html`
- `themes/modern/templates/page.html`
- 必要时抽公共 partial，减少重复输出

> 实现注记（最终评审确认）：`<head>` 属于共享的 `partials/header.html`，分享 meta 块应放入两个主题的 header partial 的 `</head>` 之前，用 `{% if share %}` 保护（其它模板不注入 `share` 时自然不输出）；四个 post/page 模板只保留对 header 的 include。

## 6. 数据来源设计

### 6.1 标题

- 文章页直接使用 `post.title`
- 独立页面直接使用 `page.title`

### 6.2 摘要

摘要规则按以下优先级：

1. 优先使用 `excerpt`
2. 若 `excerpt` 为空，则从正文内容提取纯文本摘要
3. 摘要需去除 Markdown 标记、多余空白与换行
4. 摘要长度限制在适合社交平台展示的区间，建议 120～160 个字符左右

这样既能保持作者手写摘要优先，也能保证未填写摘要时仍有可用卡片描述。

### 6.3 站点名

直接复用现有站点设置中的 `site_name`。

### 6.4 默认分享图

默认分享图直接复用站点 Logo：

- `og:image` 指向站点 Logo 的绝对地址
- `twitter:image` 指向同一地址

该方案不新增新的分享图上传流程，也不增加后台配置复杂度。

### 6.5 URL

分享相关 URL 一律使用**绝对地址**，包括：

- `canonical`
- `og:url`
- `og:image`

因此需要新增明确的站点绝对地址配置项（例如 `site_url`），例如：

- `site_url = "https://hancic.site"`

该值应作为分享卡片 URL 拼装的唯一可信来源，而不是依赖请求头临时推断。

> 实现注记：`site_url` 需包含部署子路径（如 `https://example.com/blog`），否则 `base_path != ""` 的部署下 canonical 会缺失子路径。

## 7. 字段输出规则

### 7.1 文章页输出字段

文章详情页至少输出：

- `link rel="canonical"`
- `meta property="og:type" content="article"`
- `meta property="og:title"`
- `meta property="og:description"`
- `meta property="og:url"`
- `meta property="og:site_name"`
- `meta property="og:image"`
- `meta name="twitter:card"`
- `meta name="twitter:title"`
- `meta name="twitter:description"`
- `meta name="twitter:image"`

### 7.2 独立页面输出字段

独立页面输出与文章页保持同构，确保公开页面分享体验一致。

`og:type` 第一版可统一使用 `article`，不额外区分更细页面类型，以减少兼容性判断分支。

### 7.3 Twitter Card 类型

若采用 Logo 作为默认图，建议优先使用：

- `twitter:card = summary`

这样对图片尺寸要求更宽松，首版更稳。若后续换成更适合大卡片的分享图，再考虑升级到 `summary_large_image`。

> 实现注记：实现侧当 `og_image` 存在时输出 `summary_large_image`，否则 `summary`，与上一条不冲突（有图用大卡片、无图用小卡片）。

## 8. 模板设计

### 8.1 渲染责任

模板层只负责：

- 从上下文读取 `share` 对象
- 输出标准 meta 标签

模板层不负责：

- 临时拼接绝对 URL
- 动态从正文截摘要
- 对 logo 做额外业务判断

这些逻辑应全部由后端完成，保持模板简单清晰。

### 8.2 双主题一致性

由于项目已有 `default` 与 `modern` 两套主题，本期必须两套一起支持分享卡片字段，避免不同主题行为不一致。

若后续发现两套主题头部结构重复较多，可考虑抽公共 partial，但本期以最小改动实现为先。

## 9. 错误与回退策略

### 9.1 摘要缺失

若 `excerpt` 为空，则自动从正文生成纯文本摘要。

### 9.2 Logo 缺失

若站点 Logo 未配置，则应允许回退为“无图分享卡片”，而不是渲染错误页面。

也就是说：

- `og:image` / `twitter:image` 可按条件输出
- 不能因为 Logo 缺失导致页面渲染失败

### 9.3 站点绝对地址缺失

若 `site_url` 缺失，系统可有两种选择：

- 启动时回退为空并不输出绝对分享字段
- 或运行时以保守方式回退，至少不影响页面主渲染

设计上建议把 `site_url` 作为明确配置要求，但实现上应避免因为未配置而直接把页面渲染打挂。

## 10. 测试范围

至少覆盖：

- 文章详情页输出 canonical 与分享 meta
- 独立页面输出 canonical 与分享 meta
- 有 `excerpt` 时优先使用 `excerpt`
- 无 `excerpt` 时正确回退正文摘要
- 配置 Logo 时正确输出 `og:image`
- 未配置 Logo 时页面仍可正常渲染
- 生成的 `og:url` / `canonical` 为绝对地址
- 双主题下页面头部都能输出分享字段

如现有前台测试已覆盖 `post.html` / `page.html` 响应内容，可在现有测试上扩展断言，不额外引入新测试框架。

## 11. 成功标准

视为完成需满足：

1. 文章页分享出去时，外部平台可抓到标题、摘要、站点名、URL 与默认图
2. 独立页面也具备同样的分享卡片能力
3. 分享摘要遵循“`excerpt` 优先，正文纯文本回退”的规则
4. 默认分享图直接复用站点 Logo，不新增专门分享图流程
5. 所有分享相关 URL 均使用绝对地址
6. `default` 与 `modern` 两套主题行为一致
7. 相关测试通过
